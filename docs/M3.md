# M3 — P4 Risk Engine & Auditor

**Scope:** normalize P1/P2/P3 evidence plus thresholded P5 aggregates into persistent P4 assessments and the auditor leaderboard/detail. Scores are demo triage signals, never fraud probabilities or legal conclusions.

## Demo policy

- Rule version: `demo-v1`.
- Category weights: P1 `25`, P2 `30`, P3 `35`, P5 `10`; each category contributes at most once.
- Complete-coverage labels: `LOW` 0–19, `MEDIUM` 20–49, `HIGH` 50–100.
- Any missing P1/P2/P3 evidence forces `INSUFFICIENT_DATA`. Score remains provisional and missing processes are listed.
- P5 count below 3 maps to `eligibleReportCount: null`; P4 never receives the underlying count or report rows. At least 3 reports can contribute 10.
- Rapid P1 status changes appear as informational context and contribute 0 points.
- Evaluation scenario time is fixed to `2026-10-09T09:00:00Z`; snapshot `computedAt` records actual persistence time. P3 status is evaluated as of the fixed scenario time.

## Engine and storage

- `src/domain/risk.ts` is the pure six-indicator scoring engine.
- `src/services/p4-risk.ts` recalculates P1/P2/P3 from current source rows, reads only the thresholded P5 aggregate, calculates coverage/score, and appends `RiskAssessment` plus six `RiskIndicator` rows in one serializable transaction.
- Assessments keep P2/P3 source-snapshot references, `evaluationAsOf`, `computedAt`, rule version, score, label, coverage, and thresholded P5 count. Recalculation never overwrites older snapshots.
- `src/services/auditor-risk.ts` maps safe DTOs and applies stable priority sorting. Auditor routes never serialize ORM rows or worker-level source data.
- Migration `20261011000000_m3_risk` adds scenario-time/provenance fields and weighted indicator contributions while preserving existing M1/M2 rows.

## API and screens

- `GET /api/auditor/companies?period=YYYY-MM`: company-level leaderboard, KPIs, complete priority list, separate incomplete queue.
- `GET /api/auditor/companies/:companyId/risk?period=YYYY-MM`: safe indicator detail and latest assessment history.
- `POST /api/demo/recalculate`: operator-only recalculation; production requires approved demo environment.
- `/auditor`: score/label/coverage/reasons; `/auditor/companies/[companyId]`: indicator, provenance, coverage and history.
- `/demo`: operator-key session and recalculation control. UI does not compute scores.
