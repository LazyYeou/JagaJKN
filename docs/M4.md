# M4 — Worker Transparency & Protected P5 Reports

**Scope:** worker self-service for P1/P3 plus categorical P5 submissions. No M5 polish/production onboarding or P5 free text/attachments.

## Implemented worker journeys

- `/worker` links to own contract, contribution timeline, and protected report.
- `/worker/contract` selects the contract effective for the requested month, shows immutable version history, and submits P1 feedback against a selected version.
- P1 feedback is visibly described as **linked to the account and contract**. It remains separate from P5 and is not exposed in HR/auditor DTOs.
- `/worker/contributions` shows only the signed-in worker's potongan 1% and status for the **company-period**. Labels/explanations distinguish `MATCHED`, `MISMATCH`, `PENDING`, and `UNVERIFIED`; delta is absent for pending/unverified. Mock source is labeled `Sumber: Simulasi BPJS`.
- `/worker/report` accepts period and one of the controlled categories below; no narrative or attachment fields exist.

## P5 categories and idempotency

| Code | Worker label |
|---|---|
| `POTONGAN_TIDAK_JELAS` | Potongan iuran tidak jelas |
| `KONFIRMASI_IURAN_BELUM_JELAS` | Informasi konfirmasi iuran belum jelas |
| `KETIDAKSESUAIAN_INFORMASI_KONTRAK` | Ketidaksesuaian informasi kontrak |

`POST /api/worker/reports` accepts only a random UUID-v4 `submissionId`, `YYYY-MM` period and controlled category. Company is derived from the authenticated worker's server-side scope. The UUID is the report ID, not a reporter ID, and the row has no worker/user/session/contact/IP/narrative/attachment field. Same UUID and same payload returns the same receipt; same UUID with different payload returns `409`.

Submission route does not log request body, identity, or token. UI warns that application record fields omit reporter identity but infrastructure metadata may exist; it does not promise absolute anonymity. Receipt is shown only to the submitting session and no report lookup endpoint exists.

P4's P5 adapter reads an aggregate count only. Counts 0–2 all map to `eligibleReportCount: null`; count 3+ may contribute 10. A submitted report affects auditor output only after operator recalculation.

## Verification

- Unit: controlled categories, UUID/period validation, identity/narrative field rejection, P5 threshold suppression.
- DB: duplicate sequential/concurrent UUID sends create one row; P5 schema has no reporter identity fields; sub-threshold P5 does not alter P4 score.
- API/UI smoke: own worker pages, P1 version ownership, contribution disclaimer/source label, receipt flow, retry/conflict, cross-role denial, auditor response excludes report ID/category and reporter data.

Verification completed: 22 unit tests pass; DB integration, migration backfill, API/worker-page smoke, typecheck, production build, and `npm audit` pass. P5 requests are rejected unless they contain exactly the UUID, period and category contract.

## Limitations retained

- Infrastructure access logs are outside application control; do not claim end-to-end anonymity.
- P5 is categorical only; no free text or attachments.
- Notifications and P5 aggregation are not immediate risk-score updates; operator recalculation creates a new P4 snapshot.
